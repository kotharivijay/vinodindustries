How it works (recommended)

Where it's captured: two new optional fields on the addition round — resultShadeName and resultShadeDescription. A round only sets them when the colour actually became a different shade; a plain correction leaves them blank.

Effective shade: the slip's shown shade = the latest round that set a result shade, else the original slip shade. So the read priority becomes: last addition.resultShadeName → DyeingEntry.shadeName → FoldBatch → Shade master. Every place that reads the shade (slip detail, Finish/Center, Stock, Cost report, production report) picks up T-186 automatically.

History kept: the original Milan-K cream stays on the slip and Round 1; the slip header shows "T-186 — was Milan-K cream, changed in Round 2". Nothing is overwritten, so you can always see what it started as.

Optional: a "Save as new shade to master" button on that section, so T-186's corrected recipe (original + additions) can be saved as a reusable shade — reusing the existing Save-to-Shade-Master flow.

Alternative (simpler, no schema change): just let you edit the slip's shade name/description directly and add a note. Faster to build, but loses the "was K-cream → became T-186" trail and the per-round attribution. The recommended per-round approach is the one drawn above.

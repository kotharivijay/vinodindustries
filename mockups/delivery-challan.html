Delivery Challan module — design mockup

Routes finished cloth to the right customer-facing document depending on the party tag. Pali PC Job parties → Delivery Challan (job-work, no rate). All others → Folding Despatch (full despatch with rate).

6 · Schema sketch (one table, two formats)

model DeliveryChallan {
  id              Int      @id @default(autoincrement())
  challanNo       Int      @unique          // DC-YYYY-NNN auto + manual override
  date            DateTime
  format          String                    // 'delivery-challan' | 'folding-despatch'
  partyId         Int
  party           Party    @relation(...)
  transportId     Int?
  lrNo            String?
  vehicleNo       String?

  // Routing source — every line item points to a FinishEntryLot so the
  // finished-but-not-yet-delivered queue knows what's already on a challan.
  lines           DeliveryChallanLine[]

  // Billing-side fields (null for 'delivery-challan' format)
  subTotal        Decimal? @db.Numeric(16,2)
  cgst            Decimal? @db.Numeric(16,2)
  sgst            Decimal? @db.Numeric(16,2)
  igst            Decimal? @db.Numeric(16,2)
  grandTotal      Decimal? @db.Numeric(16,2)

  notes           String?
  status          String   @default('issued')   // issued | cancelled | billed
  cancelledAt     DateTime?
  createdAt       DateTime @default(now())
  updatedAt       DateTime @updatedAt
}

model DeliveryChallanLine {
  id                Int             @id @default(autoincrement())
  challanId         Int
  challan           DeliveryChallan @relation(fields: [challanId], references: [id], onDelete: Cascade)
  finishEntryLotId  Int             @unique    // each FEL ships only once
  finishEntryLot    FinishEntryLot  @relation(fields: [finishEntryLotId], references: [id])
  lotNo             String                     // snapshot
  qualityName       String?
  shadeName         String?
  than              Int
  meter             Float?
  marka             String?
  // For folding-despatch only
  rate              Decimal?  @db.Numeric(10,2)
  amount            Decimal?  @db.Numeric(16,2)
}

Key design rule: each FinishEntryLot can appear on at most ONE challan (@unique on finishEntryLotId). That single rule keeps the queue self-cleaning — once a FEL is on a challan it disappears from the queue; cancelling the challan re-queues it automatically.

7 · Open design questions (need your call)

  1. Existing legacy Despatch — keep both for a transition, or migrate everything to the new module? Migration is straightforward but means changes to existing despatch consumers (Tally push, reports).
  2. Auto-create vs operator-create — should the queue auto-create challans (one per party per day) or always wait for operator action? Auto would save clicks but loses combine/split flexibility.
  3. Multi-day combine — should a single challan be allowed to ship FELs from different finish-program dates? (Most likely yes, but worth confirming.)
  4. GST treatment on regular flow — pull from existing party GSTIN (intra-state vs inter-state) like the inventory module already does? Should reuse the same logic, not duplicate it.
  5. Tally push — Delivery Challan format does NOT push to Tally (job-work, no sale). Folding Despatch can optionally push a Sales voucher. Confirm whether that push is needed now or later.
  6. Pali signing copy vs internal copy — need both printed at once? Currently inventory module prints two copies; same here?
Mockup only — open in any browser to preview. Once you confirm the flow + answer the open questions, I'll wire schema + APIs + UI in real code.
